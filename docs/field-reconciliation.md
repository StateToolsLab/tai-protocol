# 現行運用との照合 — 2026-09-25

## 根拠の範囲

利用者から提供された、実運用Architectによる照合便r1への返答を要約した設計記録。
案件ローカル運用についての報告であり、保守側が案件のリポジトリ・ログを直接検証した結果ではない。
公開v0.1.0との一致は未照合。案件名、個人名、内部commit、セッションID等は本書へ転記しない。
新候補のE2EやUATの合格記録として使わない。

## 確認された報告と改訂への反映（2026-09-25時点）

以下は当日の報告・判断記録。Report archive任意の扱いは、末尾の2026-09-26追補（17-J）で更新した。

| 返答で報告された運用 | 改訂への反映 |
|---|---|
| ArchitectがTask全文を起草・確定し、USERが搬送、Supervisorが実ファイルを保存・搬入 | 内容の権限と書記・保存責務を分離。保存をArchitectの前提能力にしない |
| Workerへ渡したTaskの発行commitを監査正本とする | 起草元・発行正本・archiveを区別し、実際の発行版を不変保存 |
| Supervisorが未記入statusを補った実績がある | 固定前の事前許可された整形と、固定後の内容変更を区別。差異を記録 |
| Taskの旧revisionもarchiveし、ReportはGit履歴から取得 | Reportの別archiveを一律必須にせず、固定参照・到達可能性を保持 |
| ArchitectとSupervisorの複数回の交代、savepoint・起動キットによる引継ぎ | Recovery Stateを新発明や新ファイルの強制にしない。既存文書を再利用 |
| Workerは毎便起動する固定Claude Code、Supervisorは複数候補を選ばない | まず固定接続を文書化。登録・ルーティングは将来拡張として分離 |
| 手書き転記の誤りが差し戻し原因になった | 原ツール出力の直接転送と、要約・判断の分離を明記 |

「本文を材料からSupervisorが起草する」「Workerを途中交代する」「自動で別エンジンへ
フォールバックする」運用が確認されたわけではない。新機能として扱い、実績を拡張解釈しない。

## 公開版と混同しない事項

案件報告ではGateのff統合、configへのSupervisor ID記録、ローカルsettingsによる許可を使用。
公開同梱アダプターのno-ff統合例、環境変数優先、起動allowlistと同一とは扱わない。
今回の文書補正は案件の設定・統合方式・自動起動を変更する指示ではない。
過去に差異を受容してrevisionを変えなかった例は、判断記録と実際の版を保持する。
発行正本の保存によって、起草元からの改変が自動的に検出・承認されたことにはならない。

## 未確認事項と追加照合

- 案件ローカルSKILL・Bridgeと公開v0.1.0/候補版との差分。
- 案件ローカルのmodel読取経路。指定していた事実と、起動引数へ反映された確認は別。
- settingsの実効許可一覧、起動オプションとの関係、承認履歴。
- Worker枝削除後のReport再取得の実地確認。履歴から取得した報告はあるが、枝削除の実績は未確認。
- status以外のfrontmatter補完の実績、Worker途中交代の手順。

追加採取はread-onlyを基本にし、秘密・個人情報・不要な顧客データを返送しない。
枝削除の検証は本番の枝を消さず、隔離した検証リポジトリで行う。

## 次の検証境界

文書・権限・正本の規約を補正することと、実装の動作確認は別である。
固定接続で起草→ファイル化→発行版照合→起動→Report→Gate→archiveを確認する。
整形あり/なし、保存失敗、版不一致、blocked、reset後のReport再取得、
前任会話なしの引継ぎを実環境E2E・UATの対象とする。
複数Workerルーティングのテストは、その読取・選定・起動実装を追加する際に別途設ける。

## 2026-09-26追補 — 裁定17-J（現在の採用方針）

利用者から実運用で確定した追加裁定として、次を受領した。

> 裁定17-J(2026-09-26 確定): Gate 時に .ai/task.md と同じ commit で .ai/report.md を .ai/archive/T-XXX_report_rN.md に複写してからプレースホルダへ戻す。T-126 から適用。report・diff・本文の転記はツール出力のまま行い、要約表記や「既報告どおり」等の省略は行わない(16-U)。

本候補のGitアダプターへ、Task/Report両archiveと両窓口resetを同じcleanup commitにする要件として反映する。
上表の「Reportの別archiveを一律必須にしない」は旧判断として残すが、以後のGate手順には使用しない。
T-126は元案件の適用開始点であり、他案件へ同じ番号を要求しない。過去分の自動補完・改変は行わない。
Task発行正本とReport固定版の原文を保持し、要約・参照文で実データを置換しない。
16-SのWorkerによる重複diff添付省略と、16-UのSupervisorによる原文転記・全量返送は別の規律である。
この裁定の受領・規約反映は、新候補のE2EやUAT合格を意味しない。
